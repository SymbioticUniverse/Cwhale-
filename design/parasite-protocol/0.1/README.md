# Parasite 卡片协议 0.1 施工总图

**规范草案，供宿主、插件作者和服务商联调。** Parasite 是正式产品名。当前 Cwhale APK 尚未实现本协议。首批可交付能力是目录检索、媒体试听或播放、打开来源、更新只读行情和新闻卡。支付、下单和记账提交需要另行定义授权与事务协议，宿主不得把它们注册成这里的只读查询。

| 谁来做 | 从哪里开始 | 做到什么算完成 |
|---|---|---|
| 个人作者 | 解开 [音乐样包](examples/music.pcard)，看 [清单](examples/music/manifest.json) 和下文的打包规则 | 无账号、无网络也能从自有目录搜到“两音”，点试听播放一秒本地音频 |
| 服务商 | 看 [线上握手与接口](WIRE.md)，对照 [电影样包](examples/film.pcard) 和 [五份逐包报文](examples/wire/) | 两端独立实现后，一次握手、一次查询即可生成带真实来源动作的电影卡 |
| 给已有数据源做卡的社区作者 | [新闻样包](examples/news.pcard) 和 [只读字段映射](MAPPING.md) | 使用来源已有的公开 GET 接口，无须来源方新增 Parasite 端点 |
| 社区目录及调度维护者 | [发布准入、赛马评分和首选规则](PUBLISH.md) | 同一赛题能复算分数；未授权或不满足播放条件的服务不会被推为首选 |
| 宿主开发者 | 看 [施工单和验收表](BUILD.md) 与 [机器可读契约](protocol.schema.json) | 同一实例可由点击和对话控制，切窗口、离线和重启均得到规定结果 |

这三个 ZIP 文件使用 `.pcard` 后缀。音乐样包含实际 PCM WAV 和签名，电影与新闻样包分别使用 `film.example` 和 `news.example` 文档占位域名。服务商联调时换为自己控制的域名并重新签名。签名所用的示例私钥没有分发。

## 1 架构图与信任边界

~~~mermaid

  R <-->|"仅本轮已授权的参数及简短结果"| L["用户配置的模型 API"]
  R --> D["本机调度：能力、授权、首选和排名"]
  D --> G["动作执行入口：查清单、校验参数和实例"]
  G --> C["本机目录适配器"]
  G --> H["HTTPS 适配器"]
  G --> X["公开接口映射适配器"]
  X <-->|"公开 GET 与原始 JSON"| Q["已有数据源"]
  X --> V
  H <-->|"hello / invoke"| P["本次选中的服务商"]
  C --> V["已校验的卡片数据"]
  H --> V
  V --> S["本机会话、回复版本、卡实例"]
  S --> UI["Flutter 原生卡片"]
  UI -->|"点击：同一动作入口"| G
  G --> M["本机播放器或系统来源页"]
  M -->|"真实状态回调"| S
  A["作者发布的签名包"] --> I["安装器：验签、展示权限、注册到本机"]

~~~

宿主只向本轮选中的服务商发送结构化查询。模型 API 的 Key、用户聊天、其他插件凭证和安装清单不进入服务商握手。模型可以建议操作，执行结果由适配器或播放器确认。赛马日影响候选顺序，用户指定、实际可用动作和用户权益优先。

## 2 作者交付的文件

~~~text
music.pcard                      ZIP，文件直接位于包根
  manifest.json                  UTF-8，无 BOM；清单和模板
  signature.json                 原始清单字节的签名
  assets/two-notes.wav           可选；清单包含该文件的 SHA-256
~~~

1. 复制音乐样包中的清单，替换 `pluginId`、作者、服务商、作品、资源和能力。插件 ID 使用反向域名风格的小写标识，版本使用三个非负整数。独立作者可以从本机目录开始。
2. 给每个作品一个在本服务内稳定的 `id`。同名电影的不同年份、同一首歌的不同录音版本应有各自 ID。作者负责自己提供的数据来源。历史快照记录作者、插件、服务商和作品来源，UI 将这些身份区分显示。
3. 给每个打包资源计算 SHA-256，小写十六进制写入 `assets` 表。引用形式为 `asset:assets/two-notes.wav`。填写最终清单后，以作者的 Ed25519 私钥对 **manifest.json 的原始字节**签名。签名文件的 `publicKey` 为 32 字节原始公钥，`signature` 为 64 字节原始签名，均为无填充 base64url。换行、缩进或资源变化后重新签。
4. 将清单、签名和资源压入包根。宿主先限流解包，拒绝绝对路径、反斜杠、重复名、空路径段、点路径段、大小写折叠后冲突、符号链接及未登记的额外文件。资源路径以 `assets/` 开始。校验包大小 ≤ 16 MiB，解压总量 ≤ 32 MiB，文件数 ≤ 66；清单 ≤ 256 KiB。只允许清单登记的媒体或图片资产和两份 JSON。JSON 对象重名键、非法 UTF-8 和不符合结构契约的字段一律拒绝。
5. 首次安装展示作者、公钥指纹（原始公钥 SHA-256）、域名和权限，用户确认后按插件 ID 固定公钥。签名证明同一把钥匙签过包。官方服务商认证由社区目录另行标注。后续安装同 ID 要求同一公钥且版本更高；完全相同的包重复导入视为已安装。同版本不同内容、不同公钥均拒绝覆盖。新增权限或域名需重新确认。升级须先完整验证再原子替换，失败保留旧版。

**安装本身全程离线。** 用户首次调用在线能力时，https 模式先握手，mapped 模式按已授权的映射查询公开来源。卸载撤销许可、会话令牌与插件凭证，旧聊天保留可读快照；再次播放要求插件仍有效。

## 3 一种包格式与三种适配方式

完整字段与类型见 [protocol.schema.json](protocol.schema.json)。下表和后续约束与 Schema 共同构成规范。Schema 校验形状，宿主另行检查跨字段关系和本机权限。

| 清单字段 | 施工规则 |
|---|---|
| `type / protocol / pluginId / packageVersion` | 固定类别 `manifest`。0.1 宿主接受协议字符串 `0.1`；插件包版本与协议版本分别比较 |
| `name / author / provider` | 插件名、作者、实际接入的服务方。多家内容源分别标在资源的 `sourceName` |
| `permissions / domains / assets` | 能力外的硬边界。域名精确匹配，不使用通配符。所有列表中承担身份或权限的值必须唯一 |
| `operations[]` | 一个能力在一个包中声明一次。含 `capability / description / params / view`。输入参数只允许声明过的名称；text 接受 1–256 字符，enum 必须有非空且无重复的 values，text 不得带 values |
| `adapter.mode=catalog` | 包内 `entries` 最多 200 条。为避免目录歧义，0.1 本地目录只声明一个以 `q` 为唯一必填文本参数的检索能力；可包含多个作品。每个资源 ID 唯一 |
| `adapter.mode=https` | 清单内声明 HTTPS 裸 origin 及 `auth`，必须声明 `query.remote`。所有 operation 共用同一 origin，按 capability 分派。服务商负责把自有业务数据映射成这里的结果 |
| `adapter.mode=mapped` | 社区作者声明已有公开 HTTPS GET 接口和字段映射，单 operation，必须声明 query.remote；见 [映射契约](MAPPING.md) |

本地目录搜索对查询与“标题、一个空格、副标题”分别执行 Unicode NFKC、小写转换、首尾去空格；按空白拆分查询，所有词均须为拼接字段的子串，按清单原序返回前 20 项。空查询在参数检查阶段拒绝。宿主从用户语句取作品名或作者作为 q，例如“试听两音”传 `两音`。目录命中只产生卡片，主动播放必须有明确播放意图或点击。

## 4 原生视图和动作语言

每个 operation 的 `view` 是有序组件名列表，同一组件最多一次，必须有 heading。返回 0 项显示空状态，1 项显示单卡，多项按响应顺序展示候选，初始折叠为最多 3 项并提供“显示全部”。每项实例分别绑定其来源与资源 ID。来源标记由宿主常驻绘制。浅色、深色、屏幕阅读标签、文字大小由宿主统一提供。

| 组件名 | 从当前 item 读取 | 用户动作和缺值处理 |
|---|---|---|
| heading、byline、summary | title、subtitle、summary | 后两项无值即隐藏。摘要是纯文本 |
| cover | image | 包内图片直接读取，远程图片仅在已授权源范围内加载。失败显示占位 |
| offers | offers 数组 | preview 显示“试听”或“看预告”，play 显示“播放”，open 显示“打开来源”。按钮顺序同数组。open 交给系统处理 HTTPS 来源页 |
| quote、chart | symbol、exchange、price、currency、asOf、delaySeconds；points | 显示市场、币种和报价时间；零延迟与有延迟分别标记。横轴按 UTC 时间升序，缺数据不画线 |
| range、refresh | operation 的 range 枚举及当前已校验的 args | 范围选择只替换 range，刷新沿用当前参数。复用同一只读查询，保留实例；必须按资源 ID 核对更新 |
| published | publishedAt | 显示发布者声明的时间并按设备时区格式化 |

0.1 的公共能力约定如下。声明同名能力必须采用对应入参和结果约束。作者用现有组件表达新服务时，可用以自身 pluginId 加点为前缀的自定义能力，由本机在启用后将名字、说明和参数提供给模型。新动作若需要宿主尚未提供的设备权限或写入能力，进入协议扩展流程。

| capability | 入参 | 结果约束 |
|---|---|---|
| music.search | q，必填文本 | 一个录音版本一项，subtitle 提供艺人；真实可用的试听、播放或来源动作列入 offers |
| movie.search | q，必填文本 | 一部影片一项，subtitle 区分年份或版本。预告对应 preview，正片对应 play，无播放权限可只返回 open |
| market.quote | symbol，必填文本；range，必填枚举，宿主提供 1d、1m、1y，作者可声明其中子集 | 返回 0 或 1 项，必须有 symbol、exchange、price、currency、asOf 和 delaySeconds。报价器必须给出实际数据时间。首次未指定范围用声明的首项 |
| news.search | q，必填文本 | 每项必须有 publishedAt、sourceName 和 HTTPS sourceUrl；提供跳转时用 open |

**实例动作表。** 宿主为所有卡片派发 `{instanceId, action, args}`。preview、play、open 仅在该 item 的 offers 中各出现最多一次；这三个动作的 args 为空，点击与自然语言都从该实例已验证的 offer 取目标地址。pause 仅对该实例拥有的活动播放会话有效；refresh 的 args 为空；range 的 args 只有枚举字段 `range`。后两项仅对声明对应组件的 https 或 mapped 在线查询生效。宿主根据能力与用户授权验证动作；作者不能在工具结果里新增权限或注入代码。没有 HTTPS 或媒体能力的设备仅显示还能执行的按钮，同时保留来源标记。

**实例定位。** 点击有明确实例，直接定位。对话指令先找用户明确指向的资源或上一轮候选序号，再找当前窗口最近选中的、且能执行该动作的实例。“暂停”可作用于设备唯一的活动播放会话。仍有多个有效目标时列出候选供点选。查询结果出现多个版本时，不能随意代用户播放其中一个。
